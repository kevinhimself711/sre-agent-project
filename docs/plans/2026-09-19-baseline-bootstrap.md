# 下一轮：跑通 HolmesGPT 的真实评测与轨迹闭环

## 目标与默认安排

用一周左右完成第一条可复现链路：

**部署故障 → Holmes 调用工具调查 → 提交诊断 → 官方评分 → 轨迹归档与导出 → 环境复位。**

这轮建立 baseline、验证接入风险，并积累选择 harness 改进所需的证据。后续仍允许多方向探索；本轮不提前实现记忆策略、复杂调度平台或 RL。

- 运行节点使用 **pci-2**；Windows 本地保存代码、计划和报告。
- 使用中国内地百炼按量 API，不设金额硬上限，以有限 case 数和有界重试控制规模。
- Agent 与 judge 分别配置，首选官方文档列出的 `qwen3.8-max`，先以非思考模式验证工具调用与评分兼容性。若账号不可用，依次验证 `qwen3-max`、`qwen-plus`；确定后固定配置，不在同一批实验中静默换模型。

## 实施顺序

1. **先存档本轮计划。** 下一轮 implementation 的第一个写入动作，是将本计划及已确认的模型、预算选择完整保存到 `D:\sre-agent-project\docs\plans\2026-09-19-baseline-bootstrap.md`。实施结果另写报告；发生实质调整时记录原因，保留原计划。本轮 Plan 模式不写文件。

2. **建立正式工程。** 根目录建立 Git 管理，两个上游分别克隆到 `repos/holmesgpt`、`repos/sregym`，保留各自历史和开发分支。分别固定至已调研的 `3bd44edf04f9`、`46c853db3a79`，记录完整 commit。凭据、运行产物和调研缓存加入忽略规则；不创建远程仓库或自动发布。

3. **准备独立运行环境。** 在 pci-2 使用 Python 3.12，Holmes 与 SREGym 分别使用自己的依赖环境和上游锁文件。部署命名为 `sre-agent-dev` 的 KIND 集群，沿用 SREGym 的四节点配置及 Calico。所有集群操作显式指定专用 kubeconfig，保留现有 k3s 和容器。将 inotify 限额提高到指南要求，检查节点就绪、镜像拉取、遥测和网络策略实际生效。

4. **先验证模型与原生链路。** 分别检查 Holmes 模型调用、Holmes classifier、SREGym agent/judge 的真实接口兼容性，覆盖工具调用及结果回传、评分输出解析。随后运行两个 Holmes 原生 case，并用 SREGym 原生 Stratus 完成一个 diagnosis case，确认环境、模型和评分链可以工作。

5. **接入 Holmes 并重复运行。** 为 SREGym 注册 `holmes` agent，增加 driver 和安装入口；复用原有 runner、容器隔离、评分、归档及复位机制。完成下面的轨迹适配后，再运行 Holmes 的真实 case。

## 接口与数据改动

- **Driver：** 等待 diagnosis 阶段，从 `/get_app` 获取公开任务信息，通过 SREGym 官方 MCP 调查，最后提交 `solution` 与 `stage=diagnosis`。沿用每次 attempt 的会话隔离；关闭可绕过 benchmark 权限的 Holmes 内置工具。适配层不增加 planner、答案改写或额外诊断策略。
- **提交与失败处理：** 最终提交由 driver 管理；遇到响应超时先核实宿主侧状态，无法确定时记录提交状态未知，不盲目重复提交。保留上游有界重试，不额外叠加无限重试。
- **原始轨迹：** 在模型调用边界保存每次实际 messages、tool schemas、响应和 usage；关联工具调用 ID、参数、结果、耗时、停止原因及持久化附件。压缩或摘要调用也纳入记录。需要新增记录 hook 时默认关闭，不改变 baseline 决策逻辑。
- **统一导出：** 为 Holmes 补齐 ATIF 转换，接入已有 SQLite 索引和导出。原始记录作为事实来源，ATIF 和训练样本作为派生产物；评分真值与模型可见内容分离。
- **完整性验收：** 单独检查轨迹转换、工具配对和附件完整性。转换失败不能被静默视为数据交付成功，也不能改写官方任务得分。暂不新增 REST 服务、消息队列或独立数据库平台。

## 测试规模与完成标准

首轮固定如下规模，所有尝试和失败均保留：

| 验证内容 | 运行安排 |
|---|---|
| Holmes 原生评测 | `01_how_many_pods`、`80_pvc_storage_class_mismatch`，各一次 |
| SREGym 环境对照 | Stratus 跑 `network_policy_block` 一次 |
| Holmes 接入与复位 | 同一 `network_policy_block` 连续两次，每次完整复位 |
| 第二种故障 | Holmes 跑 `wrong_service_selector_social_network` 一次 |

这两个 SREGym case 明确归为开发用例，不作为后续独立测试集。

完成标准：

- 真实链路能够获得官方诊断评分；诊断错误如实记录，不要求所有 case 答对，不以 HTTP 200 或退出码代替成功率。
- 连续运行之间没有故障、会话或记忆残留；复位失败时停止复用该环境。
- 每次模型请求与工具结果可追溯，ATIF 可验证、SQLite 可查询，重复导出不产生重复记录。
- 通过离线测试覆盖工具错误、提交响应丢失、轨迹缺失和压缩后输入记录；不为测试扩大真实故障实验规模。
- 从真实轨迹导出少量 SFT 格式样本，验证上下文时序和 tool-call 配对；未成功轨迹不冒充正样本。本轮不训练模型。

# 离线否决实验 G1 结果（glm-5.3-flash）

日期：2026-09-25

依据：`docs/plans/2026-09-23-harness-improvement-candidates.md` 第 5 节"G1 预先登记修订 v2"。修订提交为 `b93380d`，推送时间早于任何 glm 实验结果。本报告的判定全部按预先登记的判据给出，没有追加实验，也没有改动阈值。

模型与服务：newapi 网关（OpenAI 兼容接口）上的 `glm-5.3-flash`，agent 与离线 judge 使用同一模型。温度 0，`thinking={"type":"disabled"}`（该模型无法完全关闭思考，逐次记录了推理 token），agent 的 max_tokens 为 8192，judge 为 4096。judge 使用 SREGym DiagnosisJudge 原码，只替换了后端。

数据：冻结 campaign `diagnosis-20260921` 的 36 条有效 attempt 的原始轨迹（qwen3.8-max 收集）。离线实验测的是"glm 在 qwen 收集的上下文上的行为"，只用于否决和排序，不代表 glm 作为 agent 时的 live 表现。

规模与成本：

- agent 调用 1,822 次，其中强制收口 1,174 次，E8 的切点探针约 642 次；judge 调用 1,858 次。失败记录为 0，网关 503/429 共重试约 380 次。
- 强制收口调用的输入共 63,335,683 token，其中缓存 48,186,944（76.1%）；输出 1,157,177 token，其中推理 293,633。
- E8 与 judge 的用量没有记录。账单费用未知。
- 墙钟约 2 小时（agent 8 并发，judge 8 并发同时进行）。

## 2. 标定：glm judge 与对照

**E1g（glm judge 对 36 份官方提交各评 5 次）**

- 与官方判定一致：154/180。5 次评分内部不稳定的条目只有 #39；条目内 composite 标准差平均 0.015。
- 全部分歧都集中在 NML。官方判为失败的 5 条 NML（#26、#29、#34、#36、#37，官方 D1=0），glm judge 在全部 5 次重评中都给了 0.89–1.0。
- 结论：glm judge 不惩罚"把受害的 search deployment 写成故障源"这一定位错误，所以在 glm 尺度下，NML 的归因问题测不出来。非 NML 的 30 条与官方判定一致 30/30。

**E2b（原上下文 + 收口指令 N，每条 5 次，作为对照）**

- 原成功 16/16。归因错误的 8 条中 5 条成功，这 5 条正是被 glm judge 放宽的 NML。未看到证据的 network_policy 为 0/11。多数判定与官方一致 31/36，5 条差异全是 NML。
- 在 glm 尺度下，归因错误组中真正能区分成败的只剩 3 条：#23（network_policy，上下文中已有 deny-all YAML）、#32 与 #39（readiness）。
- network_policy 在离线条件下仍是 floor：未看到证据的 11 条为 0/11，#23 为 0/5。

**E2n（不加收口指令，与 Holmes 最后一步的行为一致，36 × 3）**

- 8/108 次（7.4%）一直写到 8192 token 而没有结论，分布在 7 个 attempt（#2、#6、#11、#12、#14、#21、#23），全部是 network_policy。多数判定与 E2b 相同。
- 加上 N 后，180 次中没有任何无结论输出。这支持 L6：只要 glm 用完预算，Holmes 目前的最后一步就可能得不到答案。

## 6. 对计划的影响

- **进入 live 候选的**（受 G2、G3 条件约束）：
  - T4b 加 F1：network_policy 臂，按预先登记的规则确定；
  - A2：归因臂。
  - F1 单独使用、F2、S1/S2、R3 thinking 全部淘汰，停止，不再补做。
- **工程项**：工程项 4（日志压缩）和 L6（收口指令）都有离线证据支持，放入 G0 实施。R8（服务切换适配）仍然是 G3 的前置条件。
- **需要在 G4 之前显式修订计划的一点**：A2 原定的 live 设计是在 NML 和 readiness 上各做 6 次确认。E1g 表明 glm judge 无法区分 NML 的定位错误，所以在 glm judge 下，NML 的确认没有信息量。readiness 属于中等基线类，n=6 不可能达到显著，只能报告描述统计和机制指标。这一修订应该以单独提交的形式写进计划，并且必须在任何 live 运行之前完成。
- **live judge 的影响**：如果之后的 live judge 也是 glm-5.3-flash，那么 NML 的官方式评分会系统性偏高，与历史 qwen 评分不可比。每个结果都要附上 judge 模型；跨 judge 的比较只报告机制指标。

## 7. 局限

- 离线结果是 glm 在 qwen 收集的上下文上的行为，不等于 glm 作为 agent 的 live 表现。E9（回放保真度）推迟到 G3 之后。
- 温度 0 仍有随机性，每个 attempt 取 5 个样本（E5、E6、E2n 为 3 个）按多数判定。样本量小，这里的判定只用于淘汰和排序，不能作为效果宣称。
- E3 注入的是真实对象，对象名本身就带有提示性。安慰剂控制的是注入格式，控制不了名字的提示性。外部效度需要看 holdout（G5）。
- E3c 的清单是用 #23 的对象名近似构造的。
- 故障对象类一致率是启发式指标。
- E8 的判据只看下一步，比较严格。但 S1 的获取率和获取后的动作都说明依从度确实低，淘汰结论不依赖这一点。
